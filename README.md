# 三路融合姬

Microsoft Edge Manifest V3 扩展，把两个 Bilibili 直播间的直播画面、声音、弹幕实时融合进同一块画布。当前版本 **0.3.3**。

工作台直接请求 Bilibili 播放接口和弹幕接口，在扩展内解码 HLS / HTTP-FLV，声音来自同一播放器。**无需打开直播间页面或分享屏幕。** 工作台预览和观看播放器位于同一页面，切换时沿用两路直播解码器与混合音轨；独立直播输出窗口通过本机 WebRTC 传递。两者都持续处理直播，没有先录制再处理的步骤。

## 加载与更新

1. 打开 `edge://extensions`，开启开发人员模式。
2. 点击「加载解压缩的扩展」，选择工作区的 **extension 文件夹**。
3. 点击工具栏上的「三路融合姬」进入工作台；右键「扩展选项」也可打开。
4. 更新旧版时，关闭旧工作台，在扩展管理页重新加载，再打开工作台，确认左下角 **v0.3.3**。

发布目录包含本地播放器库，加载时无需安装 Node 依赖或构建。「体验演示」可体验两路动画、合成音频和示例弹幕。

## 清新界面与快捷操作

- 雾白背景搭配薄荷绿与柔紫色，A / B 来源保持一致配色。工作台、观看页底部、弹窗和扩展入口使用统一风格。
- 左侧只保留「工作台 / 观看」两个页面入口；顶部三步流程为说明。场景管理与使用指南位于工作台顶部，布局、声音、弹幕、输出的分区定位位于工作台内部。
- 输入两路房间号后，可点击「连接全部」接入尚未连接的直播源；连接时显示进度，失败原因完整显示在卡片中。
- 画面属性标题右侧的 A / B 按钮可直接切换编辑对象；也可点击左侧预览选择。
- 工作台弹幕发送显示 30 字计数、可用目标和发送反馈；空内容、超长内容或目标未接入时停止提交。
- 观看模式保留深色画面与浅色聊天栏，下方提示空格 / M / F 快捷键；全屏仍包含发送栏。
- 布局随窗口宽度调整，中等宽度将属性与输出放在下方，窄窗口改为纵向编排。

## 使用流程

1. 分别输入 A、B 房间号或完整直播间链接，点击 **连接直播间** 或按回车。输入框右侧小图标用于查看 B 站页面。
2. 在 **直播画质** 中选择清晰度。选项来自该房间返回的列表，「当前」显示实际接入的画质。账号可用清晰度由 B 站返回，接口返回另一档时显示实际档位。
3. 用二分、画中画、单路或自由布局编排画面；拖动移动、缩放，框选裁剪直播画面。
4. 在 **音画对轴** 中把较快的一路 **整路延后**，点击「重新对齐」。画面和声音沿同一个播放器时间轴一起移动。
5. 选择 A、B 或 A+B 的声音与弹幕，调整混音和过滤，然后点击左侧 **观看**。观看页底部可以发送弹幕，支持全屏与弹幕互动。

### 观看页面

- 左侧 **工作台 / 观看** 在当前页面切换。观看模式隐藏参数面板和顶部工具栏，只保留播放器、左侧导航和底部发送栏。点击左侧 **工作台** 可继续调整；全屏时先退出全屏。连接、画质、裁剪、混音和对轴设置保留。
- 观看模式把原有解码视频移到播放器内部，由浏览器直接呈现并合成视频图层，裁剪、位置、适配、透明度和层级与预览一致。没有新增视频编码、逐帧 Canvas 拷贝或第二组直播连接。隐藏的工作台预览和电平刷新暂停，OBS 输出或录制仍按需运行。
- 观看画面按窗口尺寸与屏幕像素比显示，保留原直播解码帧的清晰度。工作台画布尺寸控制直播输出和录制；观看播放器保留相同比例，不受工作台 720p 输出尺寸限制。暂停时显示当前合成画面的定格，继续时回到实时直播。
- 自己的弹幕统一为 **金色**，其他弹幕仍按 A / B 配色。依据当前登录账号 UID 识别，观看页、工作台列表和直播输出同时生效；+1 发送的回声也会独立显示。
- 下方保留弹幕发送栏，可选择 **A、B、A+B**，输入后回车或点击发送。发送使用当前 Edge 配置中的 B 站账号；每条最多 30 个字。
- 鼠标悬停或键盘聚焦弹幕时，该条弹幕高亮并暂停滚动，出现 **复制 / +1**；离开后继续。**+1 将原文发送回该弹幕来自的房间**，不使用底部下拉框的目标。
- 点击 **全屏** 或双击画面进入全屏；全屏包含底部发送栏。按 **F** 切换全屏、**空格**暂停 / 继续、**M**切换声音，输入弹幕时快捷键不触发。
- 可单独调整观看音量和弹幕开关。操作栏静置后自动收起，底部发送栏保持可用。工作台过滤与弹幕样式同步应用到观看页。
- 进入观看后自动播放混合音频，使用播放器音量；返回工作台后恢复原本的本机监听设置。观看静音、音量和弹幕开关在切换后保留。
- 工作台 **输出设置 → 开启直播输出** 打开适合 OBS 采集的输出窗口。输出画面内包含合成弹幕；观看页在视频上独立显示可互动弹幕。

### 连接状态与声音启动

- 源卡片依次显示获取直播流、缓冲、对齐和直播中；只有播放器实际开始播放，才显示「直播中」。
- 浏览器等待声音启动时，画面与弹幕继续接入。音频区域显示 **启用声音**，点击后接入混音。
- 浏览器要求再次点击播放时，源卡片显示 **继续播放**；点击后沿用已经接入的直播流。
- 工作台直接发起直播请求；网络设置等待最多 5 秒，单次直播接口请求等待最多 15 秒，超时后保留失败原因，点击「重新连接」再试。连接过程中可随时点「断开」。
- 左侧「直播源」标题旁的 **连接信息** 显示连接步骤、HTTP 请求与响应、播放器进度、声音与弹幕状态，可复制后排查。

### 音画对轴

- **共同缓冲：2–15 秒**，为两路播放和对轴保留实时片段。
- **整路延后：每路 0–20000 ms**，同时延后画面和声音。例如 A 比 B 快 1.5 秒，将 A 设为 `1500`。
- 有 HLS Program Date Time 时按直播时间校正；其余流使用随时间推进的缓冲边缘参考。主播各自的编码与播出延迟可通过整路延后微调。
- 增大延后量时先积累足够的直播片段，界面显示缓冲进度，达到目标后继续播放。
- 混音里的 **声音微调：0–2000 ms** 单独调整音频，用于某路本身存在音画差。
- 场景保存画质、共同缓冲和整路延后设置。

### 弹幕

- 使用真实房间 ID、WBI 签名和认证令牌直接连接 WebSocket，不依赖页面节点。
- 认证、25 秒心跳、zlib 批量解压、连接超时与自动重连。
- 源卡片显示连接状态和收到的消息数，可点 **重连弹幕** 独立重连。
- A、B、A+B、关闭；关键词、用户名 / UID、受限正则过滤，8 秒去重、限流与画布样式。
- 在同一浏览器登录 B 站后，可向 A、B 或两房发送。使用当前账号会话与 CSRF，检查服务响应。同房间发送间隔 5 秒，相同房间不会重复发送。
- 登录或切换账号后点「重连弹幕」更新连接。观看和接收可使用访客身份。

### 输出与其他功能

- 独立窗口持续接收 Canvas 画面与混合音轨，支持全屏、画中画、声音开关与重连。
- OBS 添加窗口采集，选择「三路融合姬 · 直播输出」，接入窗口音频并配置直播平台推流地址，即可发送融合直播。
- 「本机监听」控制工作台声音；主音量、单路音量决定输出混音。避免同时播放工作台和输出窗口造成重音。
- 附加 WebM 录制与 PNG 截图；长时间录制可交给 OBS。
- 完整显示、等比填满、层级、坐标吸附，1080p / 720p / 竖屏 / 方形，24 / 30 / 60 FPS。
- 语音增强为高低通滤波和动态压缩，不是 AI 人声分离。
- 场景本机保存、JSON 导入导出、恢复默认。

「其他输入方式」保留标签页输入：分享页面音视频，关联 B 站页面读取与提交弹幕。直连按钮始终使用直播流，标签页输入另点「选择标签页输入」。

## 权限与数据

| 权限 | 用途 |
| --- | --- |
| storage | 场景、画质、对轴、混音与过滤设置 |
| cookies | B 站当前账号弹幕身份、发送所需 CSRF |
| declarativeNetRequestWithHostAccess | 仅为本扩展的 API、媒体和弹幕请求设置播放来源头 |
| *.bilibili.com | 播放信息、身份、弹幕会话和发送、可选页面输入 |
| *.bilivideo.com / *.bilivideo.cn / *.biliapi.net | 直播音视频片段 |

音视频在本地浏览器处理，没有额外中转服务器。令牌、签名播放地址、Cookie 不写入场景或导出文件。播放器库随扩展本地打包，不加载远程代码。扩展不设置 B 站登录 Cookie。

项目交给 OBS 等工具推流，不包含 RTMP 客户端、虚拟摄像头或 AI 声源分离。请采集和传播有权使用的直播内容。

## 开发与验证

Node.js 20+，Git 管理源代码。

本次画质、自己弹幕与持续全屏测试见 [0.3.1 验证记录](docs/validation-0.3.1.md)。观看页初版测试见 [0.3.0 验证记录](docs/validation-0.3.0.md)。连接修复的历史记录见 [0.2.2 验证记录](docs/validation-0.2.2.md)。

```powershell
npm ci
npm run vendor         # 更新本地播放器库与许可证
npm test               # 模型、签名、协议、对轴、场景和启动
npm run check          # 语法、清单、资源、CSP、产品文案
npm run preview        # 本机演示 http://127.0.0.1:4173
npm run package        # 检查和测试后打包 ZIP
npm run test:browser    # 先启动 preview；演示、编排、输出、录制、窄屏
npm run test:extension  # 工具栏、Service Worker、可选页面输入
npm run test:live       # 需 ffmpeg；HLS 解码、画质、对轴、弹幕和输出
npm run test:watch      # 先启动 preview；观看、全屏发送、悬停复制、+1、过滤与同页切换
npm run test:render     # 先启动 preview；原始解码像素对比、DPR2/4K 全屏、观看分辨率
node scripts/live-probe.mjs 84074  # 指定真实房间的只读检查
node scripts/live-probe.mjs 84074 --headed --output --duration=20  # 有窗口、默认播放策略，检查持续直播输出
node scripts/live-probe.mjs 6 --second-room=84074 --headed --output --duration=20 --block-live-worker  # 两个真实房间；后台直播消息无响应时仍能直接播放
node scripts/live-probe.mjs 6 --second-room=84074 --watch --fullscreen --duration=180 --viewport=1920x1160  # 真实双路同页全屏持续播放
node scripts/live-probe.mjs 6 --second-room=84074 --watch --headed --occluded --duration=45  # 同页观看窗口最大化
```

浏览器测试使用 Playwright 和 Edge。设置 PLAYWRIGHT_PATH 指向已有 Playwright 模块目录，或安装 Playwright。EDGE_PATH、FFMPEG_PATH 可指定程序路径。

`test:live` 模拟 API/CDN/WebSocket，播放本机生成的连续 HLS 片段，经过真实解码、混音、合成和输出链路；另模拟声音启动挂起、播放点击限制、后台无响应和连接取消。`live-probe` 以独立浏览器配置访问真实房间，报告画面、声音、弹幕与播放推进，不发送弹幕；`--output` 同时检查融合输出的持续播放和音轨。全部浏览器脚本使用默认自动播放策略。测试不读取现有登录资料，不向真实房间发消息。报告、截图、测试文件和临时配置位于 Git 忽略的 artifacts 目录。

主要模块：lib/bilibili-api.js（房间、画质、发送），wbi.js（签名），live-player.js（HLS / FLV 与对轴），live-model.js（解析和时间目标），danmaku.js（认证、心跳、解压与重连），audio.js（混音），renderer.js（合成），output-channel.js（本机 WebRTC）。

播放器库：hls.js 1.7.3、mpegts.js 1.8.2（Apache-2.0），版本锁定于 package-lock.json，本地库和许可证位于 extension/vendor。
