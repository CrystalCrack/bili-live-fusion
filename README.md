# 三路融合姬

Microsoft Edge Manifest V3 扩展，把两个 Bilibili 直播间的直播画面、声音、弹幕实时融合进同一块画布。当前版本 **0.2.0**。

房间号直接连接 Bilibili 播放接口，在扩展内解码 HLS / HTTP-FLV，声音来自同一播放器。**无需打开直播间页面或分享屏幕。** 独立输出窗口持续播放融合音视频，通过本机 WebRTC 传递，没有先录制再处理的步骤。

## 加载与更新

1. 打开 `edge://extensions`，开启开发人员模式。
2. 点击「加载解压缩的扩展」，选择工作区的 **extension 文件夹**。
3. 点击工具栏上的「三路融合姬」进入工作台；右键「扩展选项」也可打开。
4. 更新旧版时，关闭旧工作台，在扩展管理页重新加载，按浏览器提示接受新增权限，再打开工作台，确认 **0.2.0**。

发布目录包含本地播放器库，加载时无需安装 Node 依赖或构建。「体验演示」可体验两路动画、合成音频和示例弹幕。

## 使用流程

1. 分别输入 A、B 房间号或完整直播间链接，点击 **连接直播间** 或按回车。输入框右侧小图标用于查看 B 站页面。
2. 在 **直播画质** 中选择清晰度。选项来自该房间返回的列表，「当前」显示实际接入的画质。账号可用清晰度由 B 站返回，接口返回另一档时显示实际档位。
3. 用二分、画中画、单路或自由布局编排画面；拖动移动、缩放，框选裁剪直播画面。
4. 在 **音画对轴** 中把较快的一路 **整路延后**，点击「重新对齐」。画面和声音沿同一个播放器时间轴一起移动。
5. 选择 A、B 或 A+B 的声音与弹幕，调整混音和过滤，然后 **开启直播输出**。

### 音画对轴

- **共同缓冲：2–15 秒**，为两路播放和对轴保留实时片段。
- **整路延后：每路 0–20000 ms**，同时延后画面和声音。例如 A 比 B 快 1.5 秒，将 A 设为 `1500`。
- 有 HLS Program Date Time 时按直播时间校正；其余流使用随时间推进的缓冲边缘参考。主播各自的编码与播出延迟可通过整路延后微调。
- 增大延后量时先积累足够的直播片段，界面显示缓冲进度，达到目标后继续播放。
- 混音里的 **声音微调：0–2000 ms** 单独调整音频，用于某路本身存在音画差。
- 场景保存画质、共同缓冲和整路延后设置。

### 弹幕

- 使用真实房间 ID、WBI 签名和认证令牌直接连接 WebSocket，不依赖页面节点。
- 认证、25 秒心跳、zlib 批量解压、连接超时与自动重连。
- 源卡片显示连接状态和收到的消息数，可点 **重连弹幕** 独立重连。
- A、B、A+B、关闭；关键词、用户名 / UID、受限正则过滤，8 秒去重、限流与画布样式。
- 在同一浏览器登录 B 站后，可向 A、B 或两房发送。使用当前账号会话与 CSRF，检查服务响应。同房间发送间隔 5 秒，相同房间不会重复发送。
- 登录或切换账号后点「重连弹幕」更新连接。观看和接收可使用访客身份。

### 输出与其他功能

- 独立窗口持续接收 Canvas 画面与混合音轨，支持全屏、画中画、声音开关与重连。
- OBS 添加窗口采集，选择「三路融合姬 · 直播输出」，接入窗口音频并配置直播平台推流地址，即可发送融合直播。
- 「本机监听」控制工作台声音；主音量、单路音量决定输出混音。避免同时播放工作台和输出窗口造成重音。
- 附加 WebM 录制与 PNG 截图；长时间录制可交给 OBS。
- 完整显示、等比填满、层级、坐标吸附，1080p / 720p / 竖屏 / 方形，24 / 30 / 60 FPS。
- 语音增强为高低通滤波和动态压缩，不是 AI 人声分离。
- 场景本机保存、JSON 导入导出、恢复默认。

「其他输入方式」保留标签页输入：分享页面音视频，关联 B 站页面读取与提交弹幕。直连按钮始终使用直播流，标签页输入另点「选择标签页输入」。

## 权限与数据

| 权限 | 用途 |
| --- | --- |
| storage | 场景、画质、对轴、混音与过滤设置 |
| cookies | B 站当前账号弹幕身份、发送所需 CSRF |
| declarativeNetRequestWithHostAccess | 仅为本扩展的 API、媒体和弹幕请求设置播放来源头 |
| *.bilibili.com | 播放信息、身份、弹幕会话和发送、可选页面输入 |
| *.bilivideo.com / *.bilivideo.cn / *.biliapi.net | 直播音视频片段 |

音视频在本地浏览器处理，没有额外中转服务器。令牌、签名播放地址、Cookie 不写入场景或导出文件。播放器库随扩展本地打包，不加载远程代码。扩展不设置 B 站登录 Cookie。

项目交给 OBS 等工具推流，不包含 RTMP 客户端、虚拟摄像头或 AI 声源分离。请采集和传播有权使用的直播内容。

## 开发与验证

Node.js 20+，Git 管理源代码。

```powershell
npm ci
npm run vendor         # 更新本地播放器库与许可证
npm test               # 模型、签名、协议、对轴、场景和启动
npm run check          # 语法、清单、资源、CSP、产品文案
npm run preview        # 本机演示 http://127.0.0.1:4173
npm run package        # 检查和测试后打包 ZIP
npm run test:browser    # 先启动 preview；演示、编排、输出、录制、窄屏
npm run test:extension  # 工具栏、Service Worker、可选页面输入
npm run test:live       # 需 ffmpeg；HLS 解码、画质、对轴、弹幕和输出
node scripts/live-probe.mjs 6  # 指定真实房间的只读检查
```

浏览器测试使用 Playwright 和 Edge。设置 PLAYWRIGHT_PATH 指向已有 Playwright 模块目录，或安装 Playwright。EDGE_PATH、FFMPEG_PATH 可指定程序路径。

`test:live` 模拟 API/CDN/WebSocket，播放本机生成的连续 HLS 片段，经过真实解码、混音、合成和输出链路。`live-probe` 以独立浏览器配置访问真实房间，报告画面、声音、弹幕与播放推进，不发送弹幕。测试不读取现有登录资料，不向真实房间发消息。测试文件和临时配置位于 Git 忽略的 artifacts 目录。

主要模块：lib/bilibili-api.js（房间、画质、发送），wbi.js（签名），live-player.js（HLS / FLV 与对轴），live-model.js（解析和时间目标），danmaku.js（认证、心跳、解压与重连），audio.js（混音），renderer.js（合成），output-channel.js（本机 WebRTC）。

播放器库：hls.js 1.7.3、mpegts.js 1.8.2（Apache-2.0），版本锁定于 package-lock.json，本地库和许可证位于 extension/vendor。
