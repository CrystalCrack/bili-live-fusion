# 0.3.11 · 隔离原播放引擎与融合视频

## 本次反馈与调整

0.3.10 的反馈显示融合输入持续解码，合成约 1194 帧，网页视频处于非暂停状态，时间约 2.23 秒，用户仍看到闪屏。这说明暂停修复没有解决全部问题；单次记录无法证明视频在此前是否反复重建，旧版诊断会随绑定重建而清空局部记录。

代码检查确认此前将融合 MediaStream 直接赋给原引擎管理的视频元素，原引擎的媒体生命周期、错误回调和视频重建仍然存在。本次改为在原生播放器内部使用独立融合视频，原引擎保留自己的媒体元素与源，避免两者共用媒体生命周期。

- 原视频隐藏并物理静音，原流继续由原引擎加载。融合视频放在同一容器内，保留原生控制栏、全屏与网页弹幕。
- 原视频重载、程序暂停、媒体错误与元素替换不再重设融合源。原容器重建时重新挂载同一个融合视频，沿用播放意图与时间线。
- 原生控件控制融合播放、暂停、音量与静音；公开播放接口同步融合状态。全屏和尺寸变化跟随原视频几何布局。
- 实际融合帧正在呈现时，隐藏原流的加载图标和封面遮罩，防止原流状态遮住融合画面；融合帧停顿时重新显示原有提示。
- 退出或连接失败时移除融合视频，释放监听和本机媒体轨，恢复原视频可见性、音量与静音设置。
- 增加 mode、apiBridged、controlBindings、outputMounts、presentedFrames、lastPresented、lastMediaTime、maxFrameGap 诊断，记录真实画面呈现及绑定变化。

原直播连接继续运行，会增加一路网络与解码开销；本次仍为实时处理，没有录制后处理。

## 更新与试用

1. 在 Edge 扩展管理页重新加载，确认版本 0.3.11。
2. 刷新正在使用的 B 站直播页。
3. 点击插件，在当前直播页重新应用场景。
4. 观察持续播放和全屏，并试用原生暂停、继续与音量。
5. 如继续闪屏，复制播放信息反馈。mode 应为 isolated-media；presentedFrames 记录真正送到呈现回调的帧，controlBindings 与 outputMounts 记录网页视频变化。

按用户安排仅做快速代码与单元检查，包括原视频反复重载、媒体错误、替换视频、暂停继续、音量静音、全屏尺寸跟随与清理恢复。真实直播效果由用户试用反馈。
