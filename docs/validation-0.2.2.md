# 0.2.2 双路直播连接修复验证

## 问题定位

用户提供的 0.2.1 连接信息显示，声音状态为 running，房间 6 和 84074 的视频尺寸、播放进度与缓冲区均为空。获取播放信息的前台消息在 20 秒后超时，10 秒后自动重试，界面因此反复回到「连接中」。

该记录定位到工作台等待后台直播消息回复的阶段；旧记录没有后台 HTTP 阶段，不能据此将消息超时直接归因于 Bilibili HTTP 请求。此次将播放信息、弹幕连接信息和弹幕发送请求改为工作台直接执行，移除这条路径对后台消息回复的依赖。

## 修复内容

- 工作台使用 LiveSession 直接调用直播 API，连接信息标记为 studio-fetch。
- 工作台和后台共享权限检查及网络规则准备逻辑，准备过程有 5 秒截止时间，读取 Cookie 有 3 秒截止时间。
- HTTP 请求和 JSON 响应读取共同受 15 秒截止时间约束，结束后取消请求。
- 首次连接失败时保留错误状态，由用户点击重新连接；播放中的线路恢复机制继续工作。
- 连接信息包含网络准备、HTTP 路径、状态码与耗时，排除查询参数、Cookie 和令牌。
