# Edge 审核填写材料

## 单一用途

将用户指定的两个 Bilibili 直播间的实时画面、音频与弹幕融合到一个可自由编排的本地播放器，提供分屏观看、混音对轴、弹幕互动及实时融合输出。场景保存、截图和本地录制服务于同一直播融合用途。

## 权限用途

### storage

通过 chrome.storage.local 保存本机的直播间输入、画质、画面布局与裁剪、混音对轴、弹幕过滤及输出设置。用户下次打开工作台时恢复设置。存储键为 fusion-scene-v1，不使用浏览器同步存储。

### cookies

仅在已声明的 Bilibili 站点权限内使用当前浏览器的登录与访客信息，完成弹幕认证、发送及本人消息识别。代码读取 buvid3（弹幕认证访客标识）、bili_jct（用户发弹幕时的 CSRF 校验）和 DedeUserID（标签页弹幕来源的本人消息识别）。直播接口请求使用 credentials: include，由浏览器按站点规则附带 Cookie。扩展不要求用户填写账号密码，开发者不接收登录凭据。

### declarativeNetRequestWithHostAccess

为扩展自身发出的 Bilibili 直播 API、媒体及弹幕连接设置 Referer 与 Origin 请求头，以完成直播资源访问。规则以扩展 ID 作为 initiatorDomains，目标限制为清单中已授权的 Bilibili 及其直播资源域名，资源类型为 xmlhttprequest、media、websocket，不作用于其他网站的普通浏览请求。

## 远程代码

当前业务脚本、hls.js、mpegts.js 均随扩展包提供。联网获取的是直播接口数据、音视频媒体与弹幕数据；这些内容不作为 JavaScript 执行。第三方播放器许可证位于扩展 vendor 目录。后台询问是否使用远程代码时，可据此填写“否”。

## 数据使用申报依据

请按提交后台实际出现的选项申报以下数据处理，和公开隐私政策保持一致：

- 身份及认证相关信息：平台 UID、当前站点登录态、CSRF 标记与访客标识，用于身份识别、接收与发送弹幕。
- 用户内容：收到及主动发送的弹幕、昵称、所选直播音视频，用于展示、融合和互动；用户主动录制、截图时生成本地文件。
- 网站使用信息：用户输入或选择的直播间号、链接及所关联直播间标签页的标题和状态，用于接入所选直播。
- 本地设置：场景名称、布局、音量、对轴、过滤等配置，保存在设备上。
- 诊断信息：最近连接事件、房间号、画质和播放器状态，保存在当前工作台内存；用户主动点击复制后进入剪贴板。

“开发者没有自建收集服务器”与“扩展处理站点数据”应分别表述。直播接口及弹幕服务直接接收必要请求数据，用户主动发送的弹幕会提交到所选房间。

## 审核操作说明（可复制至认证备注）

扩展的用途是实时融合两个 Bilibili 直播间。点击扩展图标打开工作台，输入两个正在直播的房间号或完整链接，分别点击“连接直播间”。历史使用房间号为 6 和 84074；审核时请选用处于直播状态的房间。

可先点击“体验演示”，使用包内生成的画面、声音和示例弹幕查看布局、裁剪、混音、观看与全屏交互。演示用于了解操作；真实直播连接请按上一步进行。

连接后选择二分或画中画布局，调整画质、音量与整路延后，再点击左侧“观看”。普通观看显示右侧弹幕栏，全屏显示底部控制区和发送框；同页切回工作台可继续调整。两路视频持续实时播放，观看与切换沿用既有解码器。

接收直播与弹幕可使用访客身份。发送功能使用审核人员在同一浏览器配置中登录的 Bilibili 账号，需要由使用者主动输入或点击 +1；可在获得房间许可后检查发送。用户可选择 A、B 或 A+B 为目标。扩展不提供独立账号系统。

“输出设置 → 开启直播输出”提供实时融合窗口，可供 OBS 采集；启用输出窗口时应保持工作台运行。本地录制和截图为用户主动选择的附加操作。
